# Supabase Collaboration

## ขอบเขต

- ใช้ GitHub Pages เป็นหน้าเว็บสแกนผ่าน HTTPS
- ใช้ Supabase เป็นฐานข้อมูลกลางและระบบเข้าสู่ระบบ
- ไม่มีการสมัครสมาชิกจากหน้าเว็บ บัญชีต้องสร้างโดยผู้ดูแล
- โหลดรายการทั้งหมดของชุดงานลงเบราว์เซอร์ แล้วกรอง/แบ่งหน้าเพื่อแสดงผล
- การ์ดที่มี Barcode แล้วเป็นข้อมูลอ่านอย่างเดียว ไม่อนุญาตให้เขียนทับจากหน้าสแกน

## ตาราง

- `barcode_batches` — ชุดไฟล์งานจาก INVC
- `barcode_items` — รายการยาและผลสแกนกลาง
- `barcode_audit_logs` — ประวัติการบันทึกและส่งออก
- `profiles` — สิทธิ์ผู้ใช้ รวม `can_barcode` และ `can_import`

## ความปลอดภัย

- เปิด RLS ทุกตารางที่เกี่ยวข้อง
- ผู้ไม่เข้าสู่ระบบไม่มีสิทธิ์อ่านหรือเขียน
- ผู้เข้าสู่ระบบอ่านได้ตามนโยบาย แต่บันทึกผ่าน RPC เท่านั้น
- RPC ตรวจสิทธิ์, check digit, Barcode ซ้ำ, ค่าเดิม และรายการที่ถูกผูกแล้ว
- Publishable key อยู่ในหน้าเว็บได้ตามรูปแบบของ Supabase; ไม่มี service-role key ใน repository
- ภาพจากกล้องประมวลผลในอุปกรณ์และไม่ถูกอัปโหลด

## การสร้างบัญชี

สร้างผู้ใช้จาก Supabase Dashboard > Authentication > Users เท่านั้น จากนั้นบัญชีแรกจะเป็นผู้ดูแล ส่วนบัญชีถัดไปต้องให้ผู้ดูแลเปิดสิทธิ์จากเมนู `จัดการผู้ใช้งาน` ในเว็บ

ควรปิดตัวเลือกอนุญาตการสมัครผู้ใช้ใหม่ใน Supabase Auth เพื่อบังคับนโยบายนี้ในระดับเซิร์ฟเวอร์ด้วย
